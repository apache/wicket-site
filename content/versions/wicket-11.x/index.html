New in Wicket 11

  • A new baseline

    Wicket 11 requires Java 21 and runs on Jakarta Servlet 6.1, and its Spring integration moves to Spring 7. Applications on Wicket 10 already use jakarta.servlet, so the step up is your JDK and your container.

    Java
    21
    Jakarta Servlet
    6.1
    Spring
    7

  • One cryptography API

    Encryption is rebuilt on one authenticated scheme: encrypted URLs and stored pages cannot be altered unnoticed, the scheme generates its own key, and encrypted URLs stay cacheable. Wicket 11 can’t decrypt what Wicket 10 encrypted, so encrypted URLs and stored pages don’t survive the upgrade.

  • Leaner components

    A component keeps its model, behaviors and metadata in one compact state object instead of a packed array. In the benchmarks against Wicket 10, reading a component’s model takes half the time, and a component tree with Ajax behaviors serializes about 40% smaller, so sessions and the page store carry less.

  • Ajax without jQuery

    A second, plain JavaScript implementation of the Ajax engine with the same client-side API. Opt in, and your pages, including autocomplete, palette and the upload progress bar, no longer download jQuery. jQuery remains the default and now supports jQuery 4.

    WicketApplication.java

    @Override
protected void init() {
    super.init();
    getJavaScriptLibrarySettings().setWicketAjaxReference(
        WicketAjaxResourceReference.get());
}

  • Ajax veils

    PageVeilBehavior and LocalVeilBehavior in wicket-extensions cover a page or a single component while an Ajax request runs, so a second click on a slow button does not send the request twice. A spinner appears only when the request takes longer than 300 ms.

    BasePage.java

    public abstract class BasePage extends WebPage {
    public BasePage() {
        add(new PageVeilBehavior());
    }
}

    Download

    Source and binaries

    Most projects get Wicket through Maven or Gradle, with the dependency at the top of this page. To build Wicket yourself, or to use it without a build tool, download the source:

    • Download source apache-wicket-11.0.0.tar.gz (PGP, SHA-512 )
    • Download source apache-wicket-11.0.0.zip (PGP, SHA-512 )

    Or the binaries:

    • Download binaries apache-wicket-11.0.0-bin.tar.gz (PGP, SHA-512 )
    • Download binaries apache-wicket-11.0.0-bin.zip (PGP, SHA-512 )

    Neither package contains the libraries Wicket depends on; a build tool such as Maven or Gradle brings those in.

    Verify a download

    Check its PGP signature with the keys in the KEYS file, as the ASF explains.

    Older releases

    The mirrors carry only the latest release of each line in service. Every older release is in the Apache archives.

    Change log

    What changed in each release of this line is in the change log.

    Requirements

    The Java and Servlet API versions this line needs are at the top of the page. Some modules need more libraries, such as file upload, date and time APIs or the CDI specification; each module’s POM lists them.

    Logging

    Wicket logs through SLF4J, so your application needs an SLF4J implementation on the classpath. The SLF4J manual lists them.

    Don’t mix Wicket versions

    Use one Wicket version for every Wicket module in a project: wicket-core, wicket-extensions, wicket-spring and the others are released together and only work with the same version. Libraries built on Wicket are made for one Wicket line; use the version made for yours.
