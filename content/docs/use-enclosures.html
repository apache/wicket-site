Hide surrounding markup with wicket:enclosure

Hide a caption, label or table row together with the component it describes, without a container component in Java.

How-toWicket 10 and later

/

On this page

  • 1 Wrap the markup in wicket:enclosure
  • 2 Choose the controlling component
  • 3 Use the enclosure as an attribute
  • 4 Use enclosures around form components

This page describes Wicket 10 and later. For Wicket , see the reference guide for Wicket .

Use this when a value comes with markup that describes it, such as a caption, a <dt> or a table row, and that markup should disappear when the value’s component is hidden. Without an enclosure you would need a WebMarkupContainer around both and keep its visibility in sync.

Wrap the markup in wicket:enclosure

Put the caption and the component inside <wicket:enclosure>. When the component is invisible, Wicket leaves out everything inside the tag.

CustomerPanel.html

<dl>
  <dt>Name</dt>
  <dd wicket:id="name"></dd>
  <wicket:enclosure>
    <dt>Phone</dt>
    <dd wicket:id="phone"></dd>
  </wicket:enclosure>
</dl>

CustomerPanel.java

add(new Label("name", () -> customer.getName()));
add(new Label("phone", () -> customer.getPhone()) {
    @Override
    protected void onConfigure() {
        super.onConfigure();
        setVisible(customer.getPhone() != null);
    }
});

The components stay children of the panel in Java. Only the markup has the extra level.

Choose the controlling component

With one component inside the enclosure, that component decides. With more, name the one that decides in the child attribute; otherwise Wicket stops with Use <wicket:enclosure child='xxx'> to name the child component.

<wicket:enclosure child="phone">
  <dt>Phone</dt>
  <dd><span wicket:id="phone"></span> (<span wicket:id="phoneType"></span>)</dd>
</wicket:enclosure>

When the controlling component sits inside a container, give its path with : between the ids:

<wicket:enclosure child="contact:phone">
  <div wicket:id="contact">
    <dt>Phone</dt>
    <dd wicket:id="phone"></dd>
  </div>
</wicket:enclosure>

Use the enclosure as an attribute

When the markup to hide is a single element, put wicket:enclosure on that element instead of adding a tag around it. Leave the value empty to let the first component inside decide, or give the id of the controlling component.

<table>
  <tr wicket:enclosure="">
    <th>Phone</th>
    <td wicket:id="phone"></td>
  </tr>
</table>

This form also works with Ajax. The element gets a markup id and a placeholder of its own, and when you add the controlling component to an AjaxRequestTarget, Wicket repaints the whole element instead, so the row appears or disappears together with the value. With the <wicket:enclosure> tag, only the component itself is repainted.

Use enclosures around form components

An enclosure does not become the parent of the components inside it: in Java they stay children of the page or panel. When the enclosure is hidden because one field is invisible, the other fields in it are still part of the form. They are validated on submit, and a required field raises an error the user cannot see.

Two ways around this:

  • Add the components with queue() instead of add(). Wicket then builds the hierarchy from the markup, and the enclosure becomes the real parent of the fields. Hidden enclosure, skipped fields. See Add components without repeating the markup hierarchy.
  • Replace the tag with an EnclosureContainer: a container you add yourself, attached to an ordinary tag or a <wicket:container>, that takes its visibility from one child. Add the fields to it.
TextField<String> phone = new TextField<>("phone", phoneModel);
EnclosureContainer phoneGroup = new EnclosureContainer("phoneGroup", phone);
phoneGroup.add(phone, new TextField<>("phoneType", phoneTypeModel));
add(phoneGroup);

<wicket:container wicket:id="phoneGroup">
  <label>Phone <input wicket:id="phone"></label>
  <label>Type <input wicket:id="phoneType"></label>
</wicket:container>

EnclosureContainer renders without its own tag, so it cannot be repainted with Ajax; repaint its parent instead. For why enclosures behave this way, see How markup becomes components.

How-to guides

  • Show, hide or disable a component Hide a component or make it read-only depending on the state of your application, and decide that state once per request in onConfigure.
  • Change a tag's attributes Set, append to or remove an attribute of a component's tag from Java, with a fixed value or one that follows a model.
  • Give a component a markup id Render the HTML id attribute of a component so JavaScript, CSS, labels and Ajax can find it, and choose or generate the id yourself.
  • Group components with WebMarkupContainer Attach a plain HTML element to a container component so you can hide, disable, style or repaint a group of components as one.
  • Build a reusable panel Package a piece of user interface as a Panel, a Java class with its own HTML file, and use it on any page as often as you need.
  • Swap markup with fragments Keep small alternative pieces of markup inside a page or panel and choose in Java which one to show, without a panel class for each.
  • Wrap content with a Border Write the markup that goes around content once, as a Border, and wrap any part of a page in it while the page keeps its own components.
  • Hide surrounding markup with wicket:enclosure Hide a caption, label or table row together with the component it describes, without a container component in Java.
  • Render a component without its tag Leave out a component's own HTML tag and render only its content, and know what stops working when you do.
  • Keep preview markup out of the output Leave sample content in your HTML files so they look complete in a browser or design tool, and make sure Wicket never sends it.
  • Add behavior to a component with a Behavior Write a Behavior that changes a component's tag, adds markup around it or contributes CSS and JavaScript, and reuse it on any kind of component.
  • Add components without repeating the markup hierarchy Queue components on a page or panel and let Wicket put each one in the right container by following the nesting in the markup.
  • Generate markup from code Give a panel or page markup built in Java instead of an HTML file, and control whether Wicket caches it.
