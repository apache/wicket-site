Add CSS and JavaScript to a page

Let a component or behavior add its stylesheets, script files and start-up code to the page header with renderHead and header items.

How-toWicket 10 and later

/

On this page

  • 1 Add a stylesheet from a component
  • 2 Add a script file
  • 3 Run JavaScript when the page is ready
  • 4 Keep scripts out of the markup
  • 5 Contribute from a behavior

This page describes Wicket 10 and later. For Wicket , see the reference guide for Wicket .

Add CSS and JavaScript from Java when a component needs them: the component then brings its own files to every page it is placed on, each file appears in the header once, and Wicket adds the nonce that the Content Security Policy requires.

Add a stylesheet from a component

Put the file in the package of the component, override renderHead and render a CssHeaderItem:

CalendarPanel.java

public class CalendarPanel extends Panel {

    private static final CssResourceReference CSS =
        new CssResourceReference(CalendarPanel.class, "calendar.css");

    public CalendarPanel(String id) {
        super(id);
    }

    @Override
    public void renderHead(IHeaderResponse response) {
        super.renderHead(response);
        response.render(CssHeaderItem.forReference(CSS));
    }
}

The page gets <link rel="stylesheet" type="text/css" href="./wicket/resource/com.example.CalendarPanel/calendar-ver-….css" nonce="…"/> in its <head>. A media query goes in a second argument: CssHeaderItem.forReference(CSS, "print").

A reference is a small immutable name, so one static instance per file is enough.

Add a script file

Render a JavaScriptHeaderItem the same way:

private static final JavaScriptResourceReference JS =
    new JavaScriptResourceReference(CalendarPanel.class, "calendar.js");

@Override
public void renderHead(IHeaderResponse response) {
    super.renderHead(response);
    response.render(CssHeaderItem.forReference(CSS));
    response.render(JavaScriptHeaderItem.forReference(JS).setDefer(true));
}

setDefer(true) and setAsync(true) add the matching attributes to the <script> tag. When the script needs jQuery or another library first, declare that on the reference instead of rendering both in order, see Declare dependencies between resources.

Files that are not in a package have their own pages: Use files from the web application root, and for a CDN, JavaScriptHeaderItem.forUrl(url) and CssHeaderItem.forUrl(url).

Run JavaScript when the page is ready

Code that sets up the component goes in an OnDomReadyHeaderItem. Give the component a markup id so the script can find its element:

public CalendarPanel(String id) {
    super(id);
    setOutputMarkupId(true);
}

@Override
public void renderHead(IHeaderResponse response) {
    super.renderHead(response);
    response.render(JavaScriptHeaderItem.forReference(JS));
    response.render(OnDomReadyHeaderItem.forScript(
        "Calendar.init('" + getMarkupId() + "');"));
}

Wicket collects the ready scripts of all components into one inline script that runs when the DOM is loaded. When an Ajax request replaces the component, the script runs again after the new markup is in place, so the widget is set up again. Escape values from users before you put them in a script, for example with JavaScriptUtils.escapeQuotes.

OnDomReadyHeaderItem depends on Wicket’s JavaScript library, which Wicket renders first. By default that library is built on jQuery, so the page also loads jQuery: version 3.7.1.

To run code after images and other files have loaded, use OnLoadHeaderItem. To attach a handler to an event of an element, use OnEventHeaderItem.forComponent(component, "click", script). All header item types are listed in Header items.

Keep scripts out of the markup

Wicket’s default Content Security Policy only lets the browser run scripts and apply styles that carry the nonce of the current response. Wicket adds the nonce to every script and style it renders from a header item, including OnDomReadyHeaderItem and JavaScriptHeaderItem.forScript. Tags you type yourself get no nonce:

<!-- blocked by the default Content Security Policy -->
<script>Calendar.init('cal1');</script>
<button onclick="Calendar.today()">Today</button>
<div style="color: red">…</div>

The browser refuses to run the script and the onclick handler, ignores the style attribute, and reports a violation in its console. Move the code into a file and an OnDomReadyHeaderItem, attach handlers with OnEventHeaderItem or an Ajax behavior, and put styles in a stylesheet with a class. Configure the Content Security Policy shows how to relax the policy if you cannot avoid inline code.

Contribute from a behavior

A behavior has the same hook, with the component as an extra argument. Use it to add a script to any component without subclassing it:

public class AutoGrowBehavior extends Behavior {

    private static final JavaScriptResourceReference JS =
        new JavaScriptResourceReference(AutoGrowBehavior.class, "autogrow.js");

    @Override
    public void bind(Component component) {
        component.setOutputMarkupId(true);
    }

    @Override
    public void renderHead(Component component, IHeaderResponse response) {
        response.render(JavaScriptHeaderItem.forReference(JS));
        response.render(OnDomReadyHeaderItem.forScript(
            "AutoGrow.attach('" + component.getMarkupId() + "');"));
    }
}

add(new TextArea<>("comment", commentModel).add(new AutoGrowBehavior()));

See Add behavior to a component with a Behavior.

Add header markup with wicket:head

A panel, border or page can also put markup into the page header with <wicket:head>. Wicket adds its content once per component class, however many instances are on the page. Inline <script> and <style> in it get no nonce and are blocked like any other inline code, so use it for tags that load files, and wrap those in <wicket:link> so Wicket writes the URLs and the nonce:

CalendarPanel.html

<wicket:head>
    <wicket:link>
        <link rel="stylesheet" href="calendar.css"/>
    </wicket:link>
</wicket:head>
<wicket:panel>
    …
</wicket:panel>

Header items from renderHead take part in dependencies, ordering and bundles; the content of <wicket:head> does not.

How-to guides

  • Serve files from your Java packages Keep images, media and other files next to the component that uses them and serve them with PackageResourceReference, from Java or from markup.
  • Add CSS and JavaScript to a page Let a component or behavior add its stylesheets, script files and start-up code to the page header with renderHead and header items.
  • Use files from the web application root Add stylesheets, scripts and images that live in the web application folder, such as src/main/webapp, to your pages with ContextRelativeResourceReference and ContextImage.
  • Declare dependencies between resources Make a script or stylesheet pull in the libraries it needs by overriding getDependencies, so Wicket always renders them first and only once.
  • Combine resources into one bundle Serve several package stylesheets or scripts as one file with ResourceBundles, and replace a resource throughout the application with addResourceReplacement.
  • Put JavaScript at the end of the body Render all script header items in a container just before the closing body tag with JavaScriptFilteredIntoFooterHeaderResponse and HeaderResponseContainer.
  • Control the order of header items Put a header item first with PriorityHeaderItem, let the page's own items come before those of its components, and fix where Wicket inserts items with wicket:header-items.
  • Generate a resource in code Build files on request, such as a CSV export, a PDF or an image, by extending AbstractResource or writing a lambda, and offer them for download with ResourceLink.
  • Give a resource a URL Mount a resource reference on a path of your choice with mountResource, read path and query parameters in the resource, and link to the mounted URL.
  • Share a resource across the application Register a resource once under an application-wide key with getSharedResources and refer to it from any component with SharedResourceReference.
  • Customize where resources are loaded from Make Wicket find markup, properties and package files in a folder of the web application or the file system by adding resource finders.
  • Minify and compress CSS and JavaScript Serve pre-minified .min files, strip JavaScript in deployment mode, plug in your own CSS or JavaScript compressor, and rewrite URLs inside stylesheets with CssUrlReplacer.
  • Serve files with NIO Serve files from the file system or from inside a ZIP archive through java.nio.file.Path with FileSystemResourceReference and FileSystemResource, including byte ranges for media.
  • Show images from an external URL Render img and source tags whose URL comes from a model with ExternalImage and ExternalSource, for images on another server or a CDN.
