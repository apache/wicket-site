Keep preview markup out of the output

Leave sample content in your HTML files so they look complete in a browser or design tool, and make sure Wicket never sends it.

How-toWicket 10 and later

/

On this page

  • 1 Put preview text in the body of a component tag
  • 2 Remove whole blocks with wicket:remove
  • 3 Use the space outside wicket:panel, wicket:border and wicket:extend

This page describes Wicket 10 and later. For Wicket , see the reference guide for Wicket .

Use this when the markup files are also your design: you or a designer open them directly in a browser and want them to show realistic content, while Wicket renders the real content at runtime. Wicket has three places where preview markup is safe.

Put preview text in the body of a component tag

The body of a tag that a component replaces never reaches the browser. A Label replaces its body with the model value, so sample text in it is only for the preview:

<h1 wicket:id="title">Spring sale: 20% off</h1>
<span wicket:id="price">€ 19.95</span>

The same goes for a panel: the panel’s markup replaces the body of its tag in the page. A border is different, because it keeps the body of its tag and wraps it.

Remove whole blocks with wicket:remove

Wrap any amount of sample markup in <wicket:remove>. Wicket drops it when it reads the file.

<ul>
  <li wicket:id="products"><span wicket:id="name">First product</span></li>
  <wicket:remove>
    <li><span>Second product</span></li>
    <li><span>Third product</span></li>
  </wicket:remove>
</ul>

A list rendered by a ListView shows one sample item from its own tag; the extra items make the preview look like a real list.

<wicket:remove> must have a closing tag, and it must not contain tags with a wicket:id. If you move a component tag into it, Wicket stops with Markup remove regions must not contain Wicket component tags.

Use the space outside wicket:panel, wicket:border and wicket:extend

In the file of a panel, a border or a page that extends another page, Wicket uses only the content of <wicket:panel>, <wicket:border> or <wicket:extend>, plus any <wicket:head>. Everything around it is yours for previewing: a full page with your stylesheet, a sample header, a parent layout.

ProductPanel.html

<!DOCTYPE html>
<html xmlns:wicket="http://wicket.apache.org">
<head>
  <link rel="stylesheet" href="../../../../webapp/css/site.css">
</head>
<body>
  <main>
    <wicket:panel>
      <h2 wicket:id="name">Garden chair</h2>
      <p wicket:id="description">Weatherproof teak.</p>
    </wicket:panel>
  </main>
</body>
</html>

The <link> above only works when you open the file from disk; it is never rendered. The panel’s CSS for the real page comes from a header contribution; see Add CSS and JavaScript to a page.

Inside a border, the content of <wicket:body> is preview content as well:

<wicket:border>
  <div class="box">
    <wicket:body>Sample content that the page will put here.</wicket:body>
  </div>
</wicket:border>

  • Show, hide or disable a component Hide a component or make it read-only depending on the state of your application, and decide that state once per request in onConfigure.
  • Change a tag's attributes Set, append to or remove an attribute of a component's tag from Java, with a fixed value or one that follows a model.
  • Give a component a markup id Render the HTML id attribute of a component so JavaScript, CSS, labels and Ajax can find it, and choose or generate the id yourself.
  • Group components with WebMarkupContainer Attach a plain HTML element to a container component so you can hide, disable, style or repaint a group of components as one.
  • Build a reusable panel Package a piece of user interface as a Panel, a Java class with its own HTML file, and use it on any page as often as you need.
  • Swap markup with fragments Keep small alternative pieces of markup inside a page or panel and choose in Java which one to show, without a panel class for each.
  • Wrap content with a Border Write the markup that goes around content once, as a Border, and wrap any part of a page in it while the page keeps its own components.
  • Hide surrounding markup with wicket:enclosure Hide a caption, label or table row together with the component it describes, without a container component in Java.
  • Render a component without its tag Leave out a component's own HTML tag and render only its content, and know what stops working when you do.
  • Keep preview markup out of the output Leave sample content in your HTML files so they look complete in a browser or design tool, and make sure Wicket never sends it.
  • Add behavior to a component with a Behavior Write a Behavior that changes a component's tag, adds markup around it or contributes CSS and JavaScript, and reuse it on any kind of component.
  • Add components without repeating the markup hierarchy Queue components on a page or panel and let Wicket put each one in the right container by following the nesting in the markup.
  • Generate markup from code Give a panel or page markup built in Java instead of an HTML file, and control whether Wicket caches it.
