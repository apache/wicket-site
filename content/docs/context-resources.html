Use files from the web application root

Add stylesheets, scripts and images that live in the web application folder, such as src/main/webapp, to your pages with ContextRelativeResourceReference and ContextImage.

How-toWicket 10 and later

/

On this page

  • 1 Add a stylesheet or script from the web application folder
  • 2 Serve the minified file in deployment mode
  • 3 Link a file by URL without versioning
  • 4 Show an image from the web application folder

This page describes Wicket 10 and later. For Wicket , see the reference guide for Wicket .

Use this when a file is not part of a component but belongs to the whole site, such as a theme stylesheet, a logo or a script that a design team delivers into the web application folder:

src/main/webapp/
    css/site.css
    css/site.min.css
    js/site.js
    img/logo.png

Add a stylesheet or script from the web application folder

Create a ContextRelativeResourceReference with the path from the root of the web application, and render it as a header item, usually from a base page:

BasePage.java

public abstract class BasePage extends WebPage {

    private static final ContextRelativeResourceReference SITE_CSS =
        new ContextRelativeResourceReference("css/site.css");

    private static final ContextRelativeResourceReference SITE_JS =
        new ContextRelativeResourceReference("js/site.js", false);

    @Override
    public void renderHead(IHeaderResponse response) {
        super.renderHead(response);
        response.render(CssHeaderItem.forReference(SITE_CSS));
        response.render(JavaScriptHeaderItem.forReference(SITE_JS));
    }
}

Wicket serves the file through its resource handling, so the URL contains a version that changes with the file, the response gets long cache headers, and the tag gets the Content Security Policy nonce.

A plain <link href="/css/site.css"> or <script src="/js/site.js"> in the markup has no nonce, and the default Content Security Policy blocks it. See Configure the Content Security Policy.

Serve the minified file in deployment mode

By default the reference switches to the minified file when the application uses minified resources, which is the case in deployment mode. In the example, css/site.css becomes css/site.min.css. The reference does not fall back to the original name: when you use the default constructor, the .min file must exist next to every file you reference.

Choose per file:

Constructor Development mode Deployment mode
new ContextRelativeResourceReference("css/site.css") css/site.css css/site.min.css
new ContextRelativeResourceReference("js/site.js", false) js/site.js js/site.js
new ContextRelativeResourceReference("js/site.js", "minified") js/site.js js/site.minified.js

Whether minified files are used follows getResourceSettings().setUseMinifiedResources(…); Minify and compress CSS and JavaScript describes that setting.

Link a file by URL without versioning

CssHeaderItem.forUrl and JavaScriptHeaderItem.forUrl write the URL you give them, with the nonce. A relative URL is resolved against the root of the web application, not against the current page:

response.render(CssHeaderItem.forUrl("css/print.css", "print"));

The URL carries no version, so browsers may keep an old copy after a deployment. Use it for files that never change or that you version yourself.

Show an image from the web application folder

ContextImage renders an <img> whose src is a path from the root of the web application:

BasePage.java

add(new ContextImage("logo", "img/logo.png"));

BasePage.html

<img wicket:id="logo" alt="Example Inc."/>

The path can also come from a model, new ContextImage("logo", logoPathModel), to switch images per tenant or theme.

For files that belong to a component, prefer package resources: Serve files from your Java packages.

How-to guides

  • Serve files from your Java packages Keep images, media and other files next to the component that uses them and serve them with PackageResourceReference, from Java or from markup.
  • Add CSS and JavaScript to a page Let a component or behavior add its stylesheets, script files and start-up code to the page header with renderHead and header items.
  • Use files from the web application root Add stylesheets, scripts and images that live in the web application folder, such as src/main/webapp, to your pages with ContextRelativeResourceReference and ContextImage.
  • Declare dependencies between resources Make a script or stylesheet pull in the libraries it needs by overriding getDependencies, so Wicket always renders them first and only once.
  • Combine resources into one bundle Serve several package stylesheets or scripts as one file with ResourceBundles, and replace a resource throughout the application with addResourceReplacement.
  • Put JavaScript at the end of the body Render all script header items in a container just before the closing body tag with JavaScriptFilteredIntoFooterHeaderResponse and HeaderResponseContainer.
  • Control the order of header items Put a header item first with PriorityHeaderItem, let the page's own items come before those of its components, and fix where Wicket inserts items with wicket:header-items.
  • Generate a resource in code Build files on request, such as a CSV export, a PDF or an image, by extending AbstractResource or writing a lambda, and offer them for download with ResourceLink.
  • Give a resource a URL Mount a resource reference on a path of your choice with mountResource, read path and query parameters in the resource, and link to the mounted URL.
  • Share a resource across the application Register a resource once under an application-wide key with getSharedResources and refer to it from any component with SharedResourceReference.
  • Customize where resources are loaded from Make Wicket find markup, properties and package files in a folder of the web application or the file system by adding resource finders.
  • Minify and compress CSS and JavaScript Serve pre-minified .min files, strip JavaScript in deployment mode, plug in your own CSS or JavaScript compressor, and rewrite URLs inside stylesheets with CssUrlReplacer.
  • Serve files with NIO Serve files from the file system or from inside a ZIP archive through java.nio.file.Path with FileSystemResourceReference and FileSystemResource, including byte ranges for media.
  • Show images from an external URL Render img and source tags whose URL comes from a model with ExternalImage and ExternalSource, for images on another server or a CDN.
