Combine resources into one bundle

Serve several package stylesheets or scripts as one file with ResourceBundles, and replace a resource throughout the application with addResourceReplacement.

How-toWicket 10 and later

/

On this page

  • 1 Register a bundle
  • 2 Defer a bundled script
  • 3 Replace a resource throughout the application

This page describes Wicket 10 and later. For Wicket , see the reference guide for Wicket .

Bundle files that most pages load together, so the browser makes one request instead of several. You register the bundle once in the application; components keep rendering the individual files.

Register a bundle

Call addJavaScriptBundle or addCssBundle in init(), with a scope class, a file name for the bundle and the references it consists of:

WicketApplication.java

@Override
protected void init() {
    super.init();

    getResourceBundles().addJavaScriptBundle(WicketApplication.class, "app.js",
        ChartCoreJs.get(),
        ChartJs.get(),
        DashboardJs.get());

    getResourceBundles().addCssBundle(WicketApplication.class, "app.css",
        ChartCss.get(),
        DashboardCss.get());
}

When a component renders any of these references, Wicket renders the bundle instead. The page gets one <script> for app.js with the three files concatenated in the order you listed them, and later requests for the other members are already satisfied.

Follow these rules:

  • Members must be package resources: JavaScriptResourceReference for a JavaScript bundle, CssResourceReference for a CSS bundle.
  • List the files in the order they must run. Dependencies on references outside the bundle are kept, and Wicket renders those before the bundle.
  • A reference can be part of one bundle only. Adding it to a second bundle throws an IllegalArgumentException.
  • The name is the file name in the URL; give a JavaScript bundle a .js name and a CSS bundle a .css name.

Defer a bundled script

addJavaScriptBundle has a variant with a defer flag that renders the bundle’s <script> with the defer attribute:

getResourceBundles().addJavaScriptBundle(WicketApplication.class, "app.js", true,
    ChartCoreJs.get(), ChartJs.get(), DashboardJs.get());

A bundle is a trade-off: a page that needs one of its files downloads all of them. Put files in a bundle that appear together on most pages, and leave rarely used ones out.

Replace a resource throughout the application

WebApplication#addResourceReplacement makes Wicket render a different resource wherever the original is rendered, including in components you cannot change. Use it to serve a library from a CDN or to swap a component’s stylesheet for your own:

WicketApplication.java

@Override
protected void init() {
    super.init();

    addResourceReplacement(DatePickerCss.get(),
        new CssResourceReference(WicketApplication.class, "datepicker-theme.css"));

    addResourceReplacement(ChartCoreJs.get(),
        new UrlResourceReference(Url.parse("https://cdn.example.com/chart-core/4.4.0/chart-core.min.js")));
}

The first argument is a CssResourceReference or a JavaScriptResourceReference; the replacement can be any reference. A replaced CSS item keeps its media attribute, and a replaced script keeps defer, async and the nonce. A replacement is a bundle with one member, so the original cannot also be part of a bundle.

To replace jQuery, set the jQuery reference instead: getJavaScriptLibrarySettings().setJQueryReference(…), see Declare dependencies between resources.

How-to guides

  • Serve files from your Java packages Keep images, media and other files next to the component that uses them and serve them with PackageResourceReference, from Java or from markup.
  • Add CSS and JavaScript to a page Let a component or behavior add its stylesheets, script files and start-up code to the page header with renderHead and header items.
  • Use files from the web application root Add stylesheets, scripts and images that live in the web application folder, such as src/main/webapp, to your pages with ContextRelativeResourceReference and ContextImage.
  • Declare dependencies between resources Make a script or stylesheet pull in the libraries it needs by overriding getDependencies, so Wicket always renders them first and only once.
  • Combine resources into one bundle Serve several package stylesheets or scripts as one file with ResourceBundles, and replace a resource throughout the application with addResourceReplacement.
  • Put JavaScript at the end of the body Render all script header items in a container just before the closing body tag with JavaScriptFilteredIntoFooterHeaderResponse and HeaderResponseContainer.
  • Control the order of header items Put a header item first with PriorityHeaderItem, let the page's own items come before those of its components, and fix where Wicket inserts items with wicket:header-items.
  • Generate a resource in code Build files on request, such as a CSV export, a PDF or an image, by extending AbstractResource or writing a lambda, and offer them for download with ResourceLink.
  • Give a resource a URL Mount a resource reference on a path of your choice with mountResource, read path and query parameters in the resource, and link to the mounted URL.
  • Share a resource across the application Register a resource once under an application-wide key with getSharedResources and refer to it from any component with SharedResourceReference.
  • Customize where resources are loaded from Make Wicket find markup, properties and package files in a folder of the web application or the file system by adding resource finders.
  • Minify and compress CSS and JavaScript Serve pre-minified .min files, strip JavaScript in deployment mode, plug in your own CSS or JavaScript compressor, and rewrite URLs inside stylesheets with CssUrlReplacer.
  • Serve files with NIO Serve files from the file system or from inside a ZIP archive through java.nio.file.Path with FileSystemResourceReference and FileSystemResource, including byte ranges for media.
  • Show images from an external URL Render img and source tags whose URL comes from a model with ExternalImage and ExternalSource, for images on another server or a CDN.
