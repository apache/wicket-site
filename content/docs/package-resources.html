Serve files from your Java packages

Keep images, media and other files next to the component that uses them and serve them with PackageResourceReference, from Java or from markup.

How-toWicket 10 and later

This page describes Wicket 10 and later. For Wicket , see the reference guide for Wicket .

Put a file in the Java package of the component that uses it when the component should work wherever it is added, without anyone copying files into the web application. Wicket serves such package resources from the classpath and writes the URLs for you.

Put the file next to the class

Place the file in the same package as the component. In a Maven project, put it in src/main/java next to the class, or in src/main/resources under the same package path:

src/main/java/com/example/components/
    CalendarPanel.java
    CalendarPanel.html
    calendar.png

Files in subfolders work too: name them with a relative path such as "img/calendar.png".

Show an image from the package

Create a PackageResourceReference with a class from the package and the file name, and pass it to an Image:

CalendarPanel.java

public class CalendarPanel extends Panel {

    public CalendarPanel(String id) {
        super(id);
        add(new Image("icon", new PackageResourceReference(CalendarPanel.class, "calendar.png")));
    }
}

CalendarPanel.html

<wicket:panel>
    <img wicket:id="icon" alt="Calendar"/>
</wicket:panel>

Wicket renders a URL such as ./wicket/resource/com.example.components.CalendarPanel/calendar-ver-1712345678000.png. The version in the name changes when the file changes, so browsers can cache it safely; How Wicket serves resources explains the scheme.

Use the class name, not getClass(), as the scope. A subclass in another package would otherwise look for the file in its own package.

For stylesheets and scripts, use CssResourceReference and JavaScriptResourceReference with a header item instead, see Add CSS and JavaScript to a page.

Refer to package files from markup

Inside <wicket:link>, Wicket turns the src of <img> and <script> and the href of <link> into package resource URLs, relative to the package of the markup file:

<wicket:link>
    <img src="calendar.png" alt="Calendar"/>
    <link rel="stylesheet" href="calendar.css"/>
</wicket:link>

Wicket adds the Content Security Policy nonce to the <script> and <link> tags it rewrites this way, so they also load under the default policy. See Turn plain links into page links with wicket:link.

Offer several image sizes

Image takes more than one reference. Add srcset descriptors with setXValues and the sizes attribute with setSizes, and the browser picks the best file:

Image photo = new Image("photo",
    new PackageResourceReference(ProductPanel.class, "photo-small.jpg"),
    new PackageResourceReference(ProductPanel.class, "photo-large.jpg"),
    new PackageResourceReference(ProductPanel.class, "photo-medium.jpg"),
    new PackageResourceReference(ProductPanel.class, "photo-small.jpg"));
photo.setXValues("1024w", "640w", "320w");
photo.setSizes("(min-width: 36em) 33.3vw", "100vw");
add(photo);

The first reference becomes src, the others make up srcset. For art direction, use a Picture with Source children (both in org.apache.wicket.markup.html.image) and an Image as fallback:

Picture picture = new Picture("picture");

Source wide = new Source("wide",
    new PackageResourceReference(ProductPanel.class, "banner-wide.jpg"),
    new PackageResourceReference(ProductPanel.class, "banner-wide-2x.jpg"));
wide.setXValues("1x", "2x");
wide.setMedia("(min-width: 40em)");
picture.add(wide);

picture.add(new Image("fallback", new PackageResourceReference(ProductPanel.class, "banner.jpg")));
add(picture);

<picture wicket:id="picture">
    <source wicket:id="wide"/>
    <img wicket:id="fallback" alt="Spring sale"/>
</picture>

Embed a small image in the page

InlineImage writes the file into the src attribute as a base64 data: URI, which saves a request for small icons:

add(new InlineImage("logo", new PackageResourceReference(HeaderPanel.class, "logo.png")));

The default Content Security Policy only allows images from your own origin (img-src 'self') and blocks data: URIs. Allow them in init() before you use InlineImage:

getCspSettings().blocking().add(CSPDirective.IMG_SRC, "data:");

Stream video and audio

Video and Audio render <video> and <audio> tags for a reference. Package resources support HTTP range requests, so the browser can seek. Call readBuffered(false) so Wicket streams the file instead of loading it into memory:

add(new Video("intro",
    new PackageResourceReference(TourPage.class, "intro.mp4").readBuffered(false)));

<video wicket:id="intro" controls></video>

Two defaults stand in the way of media files. The package resource guard does not serve .mp4, .webm or .mp3; allow the extension as described in Control which package resources are served. And the default Content Security Policy sets no media-src, so it falls back to default-src 'none'; add your own origin:

getCspSettings().blocking().add(CSPDirective.MEDIA_SRC, CSPDirectiveSrcValue.SELF);

Serve a localized file

Package resources follow the same naming rules as markup and properties files. With calendar.png and calendar_fr.png in the package, a session with a French locale gets calendar_fr.png from the same reference. Styles and variations work the same way; Where Wicket looks for texts describes the lookup order.

How-to guides

  • Serve files from your Java packages Keep images, media and other files next to the component that uses them and serve them with PackageResourceReference, from Java or from markup.
  • Add CSS and JavaScript to a page Let a component or behavior add its stylesheets, script files and start-up code to the page header with renderHead and header items.
  • Use files from the web application root Add stylesheets, scripts and images that live in the web application folder, such as src/main/webapp, to your pages with ContextRelativeResourceReference and ContextImage.
  • Declare dependencies between resources Make a script or stylesheet pull in the libraries it needs by overriding getDependencies, so Wicket always renders them first and only once.
  • Combine resources into one bundle Serve several package stylesheets or scripts as one file with ResourceBundles, and replace a resource throughout the application with addResourceReplacement.
  • Put JavaScript at the end of the body Render all script header items in a container just before the closing body tag with JavaScriptFilteredIntoFooterHeaderResponse and HeaderResponseContainer.
  • Control the order of header items Put a header item first with PriorityHeaderItem, let the page's own items come before those of its components, and fix where Wicket inserts items with wicket:header-items.
  • Generate a resource in code Build files on request, such as a CSV export, a PDF or an image, by extending AbstractResource or writing a lambda, and offer them for download with ResourceLink.
  • Give a resource a URL Mount a resource reference on a path of your choice with mountResource, read path and query parameters in the resource, and link to the mounted URL.
  • Share a resource across the application Register a resource once under an application-wide key with getSharedResources and refer to it from any component with SharedResourceReference.
  • Customize where resources are loaded from Make Wicket find markup, properties and package files in a folder of the web application or the file system by adding resource finders.
  • Minify and compress CSS and JavaScript Serve pre-minified .min files, strip JavaScript in deployment mode, plug in your own CSS or JavaScript compressor, and rewrite URLs inside stylesheets with CssUrlReplacer.
  • Serve files with NIO Serve files from the file system or from inside a ZIP archive through java.nio.file.Path with FileSystemResourceReference and FileSystemResource, including byte ranges for media.
  • Show images from an external URL Render img and source tags whose URL comes from a model with ExternalImage and ExternalSource, for images on another server or a CDN.
