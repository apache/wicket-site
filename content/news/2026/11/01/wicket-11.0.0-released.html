The Apache Wicket PMC is proud to announce Apache Wicket 11.0.0, the first release of a new major version of Wicket.

Apache Wicket is an open source Java component oriented web application framework that powers thousands of web applications and web sites for governments, stores, universities, cities, banks, email providers, and more. You can find more about Apache Wicket at https://wicket.apache.org

Wicket 11 lets an application drop jQuery entirely, uses less memory and time per component, moves to Java 21 and Jakarta EE 11, and rebuilds Wicket’s encryption on a single, authenticated API. It is the first major release on our new cadence: a new major release every three months, with a long-term support release every July. Wicket 12 follows in January 2027.

Release cadence and support

Wicket 11 is the first release on the schedule we announced in September: a new major release every three months, and a long-term support (LTS) release every July.

  • Wicket 12.0.0: January 2027
  • Wicket 13.0.0: April 2027
  • Wicket 14.0.0: July 2027, the next LTS release

Only the latest quarterly release receives bug fixes and security fixes, so Wicket 11 receives them until Wicket 12 is out. Wicket 10 is the current LTS release and receives security fixes and applicable bug fixes until Wicket 14 is released. That gives you two ways to stay on a supported version:

  • follow the quarterly releases: Wicket 11 now, Wicket 12 in January, and so on;
  • stay on Wicket 10, and move to Wicket 14 when it comes out.

Wicket 9.25.0 and 8.20.0, released on 29 October 2026, were the final releases of the 9.x and 8.x lines; both have reached end of life.

New and noteworthy

Ajax without jQuery

Wicket’s client-side Ajax engine has always been built on jQuery. Wicket 11 adds a second implementation in plain JavaScript with the same public API: Wicket.Ajax, Wicket.Event, Wicket.DOM and the rest. The other framework JavaScript (autocomplete, palette, upload progress, trap focus, the debug bar, native WebSockets) no longer uses jQuery at all, so one line removes jQuery from your application:

jQuery remains the default in Wicket 11. A future major release is likely to make the plain JavaScript engine the default, so this is a good moment to try it.

Faster and leaner

Wicket 11 keeps a component’s model, behaviors and meta data in a single, simpler structure, and a link or Ajax component no longer carries extra bookkeeping for its behavior ids. Measured against Wicket 10 with the JMH benchmarks in the new wicket-benchmarks module:

  Compared with Wicket 10
Heap per component with an Ajax behavior 72 bytes less
A page of such components, serialized About 40% smaller
Reading a component’s model Half the time
Reading the behaviors of an Ajax component 82% less time
Creating and detaching an Ajax component 43% faster, half the allocation
Looking up a property, string resource or markup file Up to 6.6 times faster, 40–45% less allocation
Writing a 500-component page to the page store 16% less allocation

These are microbenchmarks; what an application gains depends on its pages.

Java 21 and Jakarta EE 11

Wicket 11 moves to the current Java platform: Java 21 and Jakarta EE 11, with Jakarta Servlet 6.1. It is built and tested with Jetty 12.1, Spring 7, CDI 5 with Weld 7, and JUnit 6. Wicket 10 required Java 17, and Wicket 8 ran on Java 8. If your application is still on Java 8, the road runs through Wicket 10 for the move from javax to jakarta, and from there to Wicket 11.

Ajax veils

PageVeilBehavior and LocalVeilBehavior in wicket-extensions block the whole page, or a single component, while an Ajax request runs. A second click on a slow button no longer sends the request twice, and a click elsewhere no longer acts on markup the response is about to replace. A spinner appears only when the request takes longer than 300 ms, and local veils nest, each with its own timings.

Uploads to a resource

FileUploadToResourceField can now take files dropped on any component (FileDropZoneBehavior) and list the chosen files with a remove button (FileListBehavior). Two files of the same name no longer overwrite each other, and a failed upload ends in onUploadFailure() instead of on the error page.

One cryptography API

Wicket 11 replaces its two encryption APIs, one for URLs and one for the page store, with a single ICrypt that always uses authenticated encryption. Choose the scheme with SecuritySettings#setCryptScheme: AES-256-GCM by default, or AES-256-GCM-SIV with Bouncy Castle.

And more

  • LoadableDetachableModel has new detach hooks: onDetach(T) receives the object that is being detached, and onDetachAlways() runs on every detach
  • AjaxFormComponentUpdatingBehavior also processes the components inside a FormComponentPanel, so the panel’s model is up to date in onUpdate()

Upgrading from Wicket 10

Wicket 11 is not a drop-in replacement for Wicket 10. Move to Java 21 and a container with Jakarta Servlet 6.1 first. The OpenRewrite recipe org.apache.wicket.MigrateToWicket11 in wicket-migration then handles the mechanical changes, including the Wicket version and the new groupId org.apache.wicket.experimental.wicket11 of the experimental modules:

Check these by hand; the migration guide has the details and the rest of the changes:

  • Wicket 11 can’t decrypt anything Wicket 10 encrypted. Encrypted URLs bookmarked under Wicket 10 no longer resolve, and pages in an encrypted page store can’t be read back after the upgrade.
  • Text fields now render required, placeholder and pattern. In a form submitted without Ajax, the browser checks them before Wicket sees the request; put novalidate on the form to keep Wicket’s validation messages.
  • The Include component and IAuthenticationStrategy, with the “remember me” support of wicket-auth-roles, are removed; both were deprecated in 10.11.0. SignInPanel and SignInPage are now UsernamePasswordPanel and UsernamePasswordPage, and the recipe renames them.
  • LoadableDetachableModel#detach() is final. Move an override to onDetachAlways(), or to onDetach() if it only applies to an attached model.

Wicket’s modules describes wicket-migration, and the documentation marks every page that needs Wicket 11 with “Wicket 11+”.

Applications on Wicket 8 or 9 move to Wicket 10 first.
